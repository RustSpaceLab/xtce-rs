First release.

Parse an [XTCE](https://www.omg.org/spec/XTCE/) definition, decode CCSDS space packets against
it, or compile it into a static Rust decoder.

## What it is tested against

Correctness here means agreement with [`lasp/space_packet_parser`][spp], not passing tests
written alongside the code. `cargo xtask diff` decodes nine definition/stream pairs — six of
them real mission downlinks — and compares every raw and engineering value of the first 64
packets field by field, then a SHA-256 over a canonical encoding of all 19 025 packets, plus
one digest per 256 packets so a divergence can be located and not merely detected. All nine
agree. The reference's output is committed, so none of that needs Python.

On top of that, 179 tests: the XML reader and IR over all 19 bundled definitions, bit reading
against a one-bit-at-a-time oracle, 29 end-to-end cases over inline XTCE, and the generated
decoder checked against the interpreted one packet for packet.

## Speed

Against the same reference on the same inputs, measured with criterion:

| | xtce-rs | `space_packet_parser` | |
|---|---|---|---|
| Load a 1.6 MB definition (CTIM, 9 493 parameters) | 10.5 ms | 120 ms | **11×** |
| Decode 1499 CTIM packets | 48 ms | 5109 ms | **106×** |
| Decode 7200 JPSS packets | 9.3 ms | 954 ms | **102×** |
| The same, through a generated decoder | 84 µs | 954 ms | **11 400×** |

## Scope

A deliberate subset of XTCE, and the divergences from the reference are deliberate too — both
are written down in [`SUPPORTED.md`](../../SUPPORTED.md), with what each one costs. Telemetry
and telecommands both load; the reference has no command support at all, so there the schema
is the oracle.

Not published to crates.io yet.
